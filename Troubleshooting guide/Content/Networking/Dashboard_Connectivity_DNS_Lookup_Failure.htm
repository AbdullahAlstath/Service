Dashboard Connectivity DNS Lookup Failure

Error Code

Domain Name Service (DNS) Look Up reports “Bad” when running the Connectivity Tester in Dashboard when testing for Remote Diagnostics (Pro360/SecureLink) and Remote Send Logs (RSL).

Complaint Description

When running the Dashboard Connectivity Tester, DNS Look Up reports “Bad”, including Access over 22/443. LAN Connection results “Good”.

Technical Support

Verify Physical Connectivity of Network Devices

It is possible that there could be a bad ethernet cable, or the network devices (Panther, switch, firewall, customer wall port) might not be correctly plugged into the appropriate network device.

Resolution:

Check Network Device Connectivity

  1. Verify that the Panther is properly plugged into the next network device.
    1. If the Panther is plugged into a switch, verify that the Panther is connected to the switch on ports 1-16. Look for the presence of link lights on either the switch or the Panther.

      Figure 1: Example of Network Interface Card Link Lights

    2. If the Panther is plugged into a firewall, verify that the Panther is connected on ports 1-7 (5505) or 8 (5506-X). Look for the presence of link lights on either the firewall or the Panther.
  2. If applicable, verify the switch is plugged into the firewall on either port 7 (5505) or port 8 (5506-X). Look for the presence of link lights on either the firewall or the switch.
  3. Verify the firewall is plugged into the customer wall port on either port 0 (5505) or port 1 (5506-X). Look for the presence of link lights on the firewall.

Test:

Retry Connectivity Tester.

Field Service

Network Interface Card (NIC) DNS Server Address Configuration

The Panther NIC may not have been correctly configured to include the appropriate DNS server, as designated by the customer.

Resolution:

Configure or validate the DNS Server into the NIC.

  1. At the Panther Command Prompt, type “control ncpa.cpl”.
  2. Right-click on the NIC and click “Properties”.
  3. Click on Internet Protocol Version 4 (TCP/IPv4) and click “Properties”.
  4. Click the radio button for “Use the following DNS server addresses:” and input the following addresses:
    • Preferred DNS server: Customer Specific
    • Alternate DNS server: Customer Specific
    Note—The DNS server is customer specific. Please refer to the generated instructions.txt file when programming the firewall to determine the IP address.

Test:

Retry Connectivity Tester.

Firewall DNS Server Address Configuration

When configuring the firewall, the customer determines whether they would like to use their local DNS servers or if they want to use a publicly available DNS server (e.g., Google DNS, OpenDNS). The firewall is configured to only allow traffic to two specific DNS servers. These servers must match between the Panther NIC and the firewall.

Resolution:

Verify the DNS server IPs are programmed into the firewall.

  1. Connect to the console port of the firewall.
  2. Using Firewall Wizard 6.1.0.4, select the option “Save the current firewall configuration.”
  3. Select the appropriate location to save the files.
  4. Run Wizard to completion, navigate to the saved location from Step 3 and open the output.txt file.
  5. In the file, search for “object-group network DNS” servers. Below that line there are two lines that start with “network-object”. Immediately following “network-object” are the IPs of the DNS servers.

Test:

Validate DNS servers match between firewall and Panther NIC, Retry Connectivity Tester

Customer IT Escalation

If the Connectivity Tester reports “Bad” after confirming the DNS servers match, contact the customer’s IT department to determine if these are the correct DNS match.

Resolution:

Contact Customer IT for further instructions.

Test:

Retry Connectivity Tester.
