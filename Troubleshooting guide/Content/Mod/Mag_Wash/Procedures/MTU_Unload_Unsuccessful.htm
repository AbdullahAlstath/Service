Resolution

Inspect incubator carefully:

  • Debris
  • Carousel, belt, teeth, mtu slots
  • Sensor not calibrated
  • Dirty sensor
  • Misaligned sensor
  • Damaged sensor

Panther Case Study – MTU Unload Unsuccessful. Instrument 01217, 2016.12.08.

Health Report shows:

“MTU Unload unsuccessful. Could not unload one position. Please run Force MTU Unload.”

Followed by:

“No MTU was detected, unloading of MTUs is completed.”

Health Report Screen Shot:

Background on how the instrument works:

When the instrument starts up, there is an MTU count. How this happens is the LD checks all of the slots, except the incubators. For the MTU check in the incubators, each incubator does a “check all slots” command (incubator command 54). This is how the instrument knows if there are any MTUs to unload.

What is happening on this Instrument:

What can happen is that the incubator MTU sensor gets dirty (or malfunctions), and the sensor sees an MTU when there isn’t actually one there. So, the incubator “tells” the Distributor there is an MTU to unload, and the Distributor goes to get it, but there isn’t actually an MTU, so the “MTU Unload Unsuccessful” error happens.

To find which incubator is faulty, you search the low level logs for the following strings:

Search String Description
COP -> PC 20 54 HT Incubator Check all Slots Response
COP -> PC 21 54 Trans Incubator Check all Slots Response
COP -> PC 22 54 Amp Incubator Check all Slots Response

In this case, the Transition Incubator is the one sensing the Phantom MTU. Search Result:

2016-12-07 04:41:24,827|[StSerClient:COP->PC]|RS232Ctrl|RS232Communication|Info|Normal|COP->PC 21 54 00 02 00 00 08 00 00.

If there are no MTUs present, then the last 4 bytes (highlighted in yellow) should be zeros. In this case, the last 4 bytes are 00 08 00 00. To see where the MTU is being sensed, you have to invert the bytes and convert from hex to binary:

  1. Invert: 00 08 00 00 inverts to 00 00 08 00.
  2. Remove the leading zeros and concatenate: 00 00 08 00 -> 800hex.
  3. Convert to Binary: 800hex = 100000000000 bin.
  4. Slots are counted right to left. So, the incubator is sensing an mtu in slot 12.

Service Plan

To service, first, always verify that there truly is not an MTU in the incubator slot. Also verify the Distributor teaching to the suspect incubator is good.

From there, check / replace the Incubator internal PCB (p/n 902789), which has the MTU sensor on it. (Part should be in trunk stock.)
