Analyze Flags and Message Codes

This topic explains how to analyze flags and message codes, to determine which module generated the code.

Recommended Analysis Procedure for Error or Processing Code

Perform this procedure for either Error codes, or Processing codes:
  1. Review the Result Log for flags (i.e., result and assay processing codes) and Message (Event) Log for messages (i.e., message Event ID error codes).

If no Message/Event Log is available, then review the When Message/Event Log has been purged section below.

                                           1 - PC Event                   2 - COP Event

The Event ID number signifies what type of event is occurring (i. e., PC or COP event as shown in the graphic above.)
  1. Review the Message (Event) Log to find the local time stamp and event/flag that was assigned during assay processing. Search for the oldest entry's local Date and Time and Event ID number.

When the Message/Event Log has been purged:

  • Select Reports button in the Panther Menu bar.

The Report Menu will appear that shows all of the possible reports, checklists, worklists, and logs available for review.
  • In the Report Menu, select the applicable Creation Date option to find the Panther's Historical Data that contains the particular time period that needs to be investigated in the Message/Event Log information.
  • Select View (or Print) to review the Message Log for the chosen Creation Date. (These buttons are located at the bottom edge of the Report Menu screen.)

Use the Results Log for Flags

Perform this procedure to find any result or assay processing codes:
  • Select Results in the PANTHER Menu bar.
  

                  1 - Assay Processing Code                   2 - Result Processing Code(s)
  • The Results Log for the selected Completion Date will appear.
  • Review the entire fifth column (moving left-to-right) for both result and/or assay processing codes (i.e., for any result or assay flags).
  

Use the Message Log for Error Codes

Perform this procedure to find any result or assay processing codes:
  • Select Messages button in the PANTHER Menu bar
  • The Message Log (table) for the selected Completion Date will appear.
  • Review the entire Event ID column for any suspectious result and/or assay processing codes (i.e., for any flags).

Decipher the Event ID Number

The Event ID number format is NNN.NNN.NNNNN, where:

  • The first number set or NNN." is the Module ID number for all events that post from any COP or device firmware.
  • The second number set or ".NNN." is the SubUnit ID number which specifies the subunit in which the event occurred.
  • The third number set or ".NNNNN" is the Message Number which specifies the acutal event that occurred. The message event numbers are documented in the module design description of the firmware. For PC event numbers are defined in the file PCEVENTS.TXT.

Module ID Number

As described in the last section, the Module ID number is the first number set of the Event ID Number.

Each PANTHER module's CAN Bus Address is the Module ID number which ranges from 0 to 255. On the PC side, the CAN Bus Address for the Module ID number ranges from 256 to 511.

The Module ID number is mapped to a certain dynamic link library (.dll) module, and from this library module is where the event is generated.

SubUnit Number

The SubUnit number further details the origin of the event.

Message Number

Both COP and PC events are subject to localization, specifically, during the build process, the two files are converted into a dot.net assembly file (i.e., Eventmessages.dll). This .dll file contains all Event messages as string resources, which in turn contain the Event ID number in a period-separated format.

Use the ViewLog

This log can be viewed by opening the ViewLog application from within PANTHER Tools or through the Remote Dashboard (using its menu path File > View Log. This log lists all the events or flags with assigned 'local time' and 'UTC GMT' time stamps.

While viewing the ViewLog data, the FSEField Service Engineer. should perform root cause analysis, then identify the instrument problem by using the step-by-step procedure in the Service Software.

<Photo of ViewLog with the EventLogEntries tab selected.>

The EventLogEntries tab
  1. Click the EventLogEntries tab to obtain the local and GMT time stamps for all events or flags that occurred during a particular day (see ViewLog capture above).
<Photo of ViewLog with the Log tab selected (with 7 elements in command string being number-labeled.>
  1. Click the Log tab to see specific error message codes (listed under the Content column). These message codes are listed by their occurrence associated Date, Time, Thread, Class Name, Category, and Error Level.
  2. The Content column contains the Receipt Command String for each message/flag code. This command string includes the affected:
  • Device address
  • Answer ID
  • Receive State
  • Subassembly name
  • Error or warning
  • Position
  • Options
