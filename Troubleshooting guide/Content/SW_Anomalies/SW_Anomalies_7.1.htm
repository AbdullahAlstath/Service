2074692

Master lot

Customer was also unable to load an ATV kit onto the instrument and would get an “invalid kit” message error by either loading kit or scanning MLBS (ML266751). Software team found that the issue was caused by the failing hard drive on the previous PC. When the user activated the lot for the first time, there are CommitFailedExceptions which occurred when attempting to write the ML into the database. When these exceptions occur, the system retries the transaction, even though we do not know whether the commit failed or was successful. In this case, the system successfully committed the row twice prior to the transaction completing successfully with confirmation. Meaning, there are now three items in the DB which correspond to this ML. This then leads to an ambiguous master lot check and thus the kit for this ML cannot be loaded.

We recommend that the customer backs up all necessary data from the system and deletes the database.

Software exception

Customer experienced a SW exception shortly after assignment on an LDT Control. Root Cause: 1. User manually deletes the test orders that were assigned via sample defaults. 2. Shortly after, the user selects the sample to be assigned as a control. 3. The UI thinks that test orders are still available to be deleted and attempts to do so. 4. The test orders have already been deleted though and thus the “Sequence contains no elements” error occurs because UI expected the command to return the deleted DBIds.

A workflow change could help to mitigate this issue. The customer is using sample defaults to assign the test orders. Which forces them to delete the test orders and thus helps to lead to this exception. 1. Turn off sample defaults when loading the rack with controls. Turn back on after loading the rack. 2. Load the rack with controls first, delete the test orders, load all remaining specimen racks, and then assign as an LDT control. The key is that we need to give some time for the delete to successfully take place and propagate to the UI. Or to eliminate the delete by turning off sample defaults.

2139332

Slow

The short description: Customer is reporting Instrument is pipetting slower than expected. It takes 10 min to pipet 5 samples instead of 5 min When does this issue occur (on Panther only)? On instruments with software 7.1 when one of the Universal fluids kits is empty at the beginning of assay processing. What is the software anomaly? Even though one of the fluids kit is invalid, the system allows it to be scheduled for Lead prime MTU (LPM). The system should be taking into account kit validity when selecting the kit for leading prime.

The longer description: When starting assay processing, a condition exists when one of the UF kits is invalid. An invalid kit is either an expired or empty kit. The system will report that it is in the Ready state as there is still a valid UF kit on board. When AP is started, the system must introduce an LPM (Leading Prime MTU) to prime both MW stations. Even though the kit is invalid, the system allows it to be scheduled for LPM. Because the fluid kit is invalid, however, a secondary check stops it from being used for priming. Leading to the condition where a MW station cannot be used for AP and thus results in a 10-minute MTU introduction cycle.

Regular Panthers will only experience the defect during AP. It will not occur at initial startup of the instrument because the Prime task requires both kits to be valid. It can occur when the system has completed an AP session and moves to the Ready state. In this case, the defect will occur if AP is started with an invalid kit or a kit moves to invalid during AP and an LPM is required. An LPM would be needed by the system if the current assay being processed switches between TMA, Fusion, or RT.

On Panther Plus: there are 2 different customer perceived scenarios depending on which fluids kit the instrument decides to use for the LPM. If kit A is empty and instrument decides to use kit A for LPM à Instrument continuously transitions from Assay Processing to Ready (see MKS# 2047987) If kit A is empty and instrument decides to use kit B for LPM same as on Panther: Pipetting is slower than expected. It takes 10 min to pipet 5 samples instead of 5 min. (MKS# 2139332).

The customer must check the UF status when in the Ready state. If one of the kits shows as invalid, it must be replaced. This will bring the system back to the Setup state and require a Prime of the system in order to continue to AP.
