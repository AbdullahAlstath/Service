SW 7.1 - Fusion Software Exception After Assigning LDT Control

Software Exception After Assignment on LDT Control

Issue:

Customer experienced a SW exception shortly after assignment on an LDT Control.

MKS:

2099423

Root Cause:

  • User manually deletes the test orders that were assigned via sample defaults.
  • Shortly after, the user selects the sample to be assigned as a control.
  • The UI thinks that test orders are still available to be deleted and attempts to do so.
  • The test orders have already been deleted, though, and thus the Sequence contains no elements error occurs because UI expected the command to return the deleted DBIds.

Workaround:

A workflow change could help to mitigate this issue. The customer is using sample defaults to assign the test orders, which forces them to delete the test orders and thus helps to lead to this exception.

  1. Turn off sample defaults when loading the rack with controls. Turn back on after loading the rack.
  2. Load the rack with controls first, delete the test orders, load all remaining specimen racks, and then assign as an LDT control.

The key is that we need to give some time for the delete to successfully take place and propagate to the UI, or to eliminate the delete by turning off sample defaults.
