MTU Sidecar Reports Too Many or Too Few Tests

Complaint Description

MTU Sidecar reports too many or too few tests.

TABLE OF CONTENTS

  • Field Service

    End of travel teaching is incorrect

Technical Support

N/A

Field Service

End of travel teaching is incorrect

Teaching was performed without a carrier in the Loading Drawer.

Teaching was performed with MTUs in the carrier.

Resolution:

Perform AutoTeach End of Travel, and ensure there is an empty carrier installed in the Loading Drawer.

Test:

Start Panther, load MTUs, and verify GUIGraphical User Interface – allows users to interact with the software using images, graphical icons, and visual indicators rather than text commands. count matches actual count.

To check if the teaching is incorrect, use the following regex search in file locator lite:

fwp.*mtuexpansion: 288 OR viewlog 0x2c24[11300]

Expected value is around 11300. this would be 20 MTUs, or 100 tests. For example:

2022-12-10 19:12:40,660|[FWParam]|ManualActions|ManualActions|Info|Norma|FWP: MtuExpansion: 288: nelxt index: 290, type UnsignedInt DefaultValue 0x2C24[11300] Value 0x2C04[11268]

Each MTU is 508 steps in width. So, if the teaching is incorrect, expect the parameter value to be around 12300, if the FSEField Service Engineer. taught without a carrier installed. For example:

2022-12-14 12:49:22,358|[FWParam]|ManualActions|ManualActions|Info|Normal|FWP: MtuExpansion: 288: next index: 290, type UnsignedInt DefaultValue 0x2C24[11300] Value 0x2F8C[12172]

If it is taught wrong, then you can get funky errors, like the expansion queue is empty because it is expecting 110 tests, but there are only 100 in there.

This can also cause this error: (03866, 2022.12.22)

2022-12-22 15:55:13,561 [E] COP Fatal High COP error (Worklist command execution timeout Device 0x7, SubAssembly: 0x1) (LowLevelEvent) [0x00.0x06.0x0010] bytes: 00 06 03 06 10 14 06 58 01 58 02 58 01 58 01 58 01 58 01 02 57 4C 07 40 00 01 [000.006.00016]
